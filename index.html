02 — Método

Documentación que se puede leer. Código que se puede correr.

La diferencia entre una demo y un proyecto no es la cantidad de features: es saber qué hace, por qué está hecho así y dónde se rompe.

01

Del problema al pin

Cada proyecto arranca con un problema concreto y termina en un mapa de hardware, un protocolo y un comando reproducible. El diagrama no es decoración: es la arquitectura.

02

Decisiones, no folletos

Los README explican qué se descartó, qué se rompió y por qué se eligió cada camino. Los límites y la deuda técnica están escritos, no escondidos.

03

Límites a la vista

Las métricas salen de mediciones reales. Si algo no se pudo probar —una cámara, un CAN físico, un pago mainnet— se dice explícitamente y se explica qué falta.
