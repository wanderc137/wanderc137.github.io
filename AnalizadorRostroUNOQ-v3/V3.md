## 2. IP Webcam editable desde la interfaz

En la barra superior hay un campo **IP Webcam** que acepta:

- solo la IP: `192.168.10.249` → `http://192.168.10.249:8080/video`;
- IP y puerto: `192.168.10.249:8080`;
- URL completa: `http://192.168.10.249:8080/video` (también `https`, `rtsp`, `rtmp`);
- una URL de foto (`/photo.jpg`, `/stream`, `/`) → se canoniza a `/video`.

Flujo:

1. **Probar** llama a `GET /api/camera/probe?url=...`, descarga un still de
   `/photo.jpg` (timeout 3 s) y devuelve la resolución sin cortar el stream.
2. **Aplicar** llama a `POST /api/camera/source`, detiene pipeline y cámara,
   aplica la fuente nueva, espera hasta 8 s el primer frame y reanuda el
   pipeline.
3. Si el primer frame no llega, se restaura la fuente anterior y se devuelve
   `503` con el detalle; la demo no queda sin vídeo.
4. Al tener éxito, la URL canónica se guarda en la línea `CAMERA_SOURCE` de
   `.env` (si el FS es de solo lectura, la respuesta trae `persisted=false` y
   el cambio queda solo en runtime).

Valor usado en la demo: `http://192.168.10.249:8080/video` (teléfono con IP
Webcam en la red `192.168.10.0/24`). La placa ya tenía ese valor en su `.env`;
la V3 lo deja también como valor por defecto de `.env.example` y `.env`.

## 3. Endpoints nuevos

| Método | Ruta | Función |
|---|---|---|
| `GET` | `/api/camera/probe?url=...` | Normaliza y valida la IP/URL con `/photo.jpg` |
| `POST` | `/api/camera/source` | Body `{"source": "..."}` o `{"ip": "..."}`; reconecta y persiste |

Ambos respetan `API_TOKEN` cuando está configurado (header `X-Api-Token`).

```bash
sudo sed -i 's/unoq-app-v2/unoq-app-v3/g; s/AnalizadorRostroUNOQ v2/AnalizadorRostroUNOQ v3/' /etc/systemd/system/unoq-app-v3.service
sudo systemctl daemon-reload
sudo systemctl enable --now unoq-app-v3
```
